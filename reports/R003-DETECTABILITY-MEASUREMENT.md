## 2. T8 — Hashem protocol resolution

For R-003, T8 is not a single new wire protocol.

The Hashem upstream architecture describes:

1. a GRE Layer-3 link between the two servers; and
2. an FRP reverse relay associated with that link.

The exact observable T8 fingerprint therefore depends on the installed FRP version and its transport settings. R-003 freezes and records:

- Hashem commit/version;
- FRP version;
- `transport.protocol`;
- `transport.tls.enable`;
- related TLS options;
- config hash.

Modern FRP versions enable TLS by default, so a Hashem result is not interpretable unless the actual FRP version/config is preserved.

## 4. Frozen definitions

Sampling interval: 60 seconds.

**First disruption**

First sample in three consecutive tunnel-health failures, after at least ten prior healthy samples.

**Full block**

Thirty consecutive minutes of tunnel-health failure while foreign-side controls show that the dedicated server remains healthy.

Classification is evidence-based:

- `ip-wide`
- `port-only`
- `sni`
- `protocol-reset` / protocol-or-app failure candidate
- `throttling`
- `server-side`
- `isp-outage`
- `unknown`

An isolated reset or packet-loss event is not labeled a block.

## 5. Traffic equality

Profile A is generated from one deterministic schedule seed and reused for every tunnel/ISP pair.

Profile B is generated by the same driver with one frozen target bitrate (default template: 7.5 Mbit/s) for 30-minute blocks.

Each event records:

- attempted bytes;
- delivered bytes;
- elapsed time;
- success/failure;
- aggregate delivery ratio.

The profile must not be adapted after a tunnel begins failing.

## 6. Passive-probe evidence

Foreign capture is passive only.

Private evidence records source IP, time, connection metadata, TLS ClientHello/HTTP request information when observable, and pcap.

The shared report removes source IPs. It may contain:

- number of unique unsolicited sources;
- salted one-study pseudonyms;
- ASN aggregates;
- first probe time;
- cover fetch observations;
- temporal distance between probe and later disruption/block.

A probe preceding a block is reported as temporal sequence, not proof of causation.

## 7. What cannot yet be truthfully populated

The requested tunnel × ISP survival table cannot be populated from CI or local simulation.

It requires the physical experiment:

- ten fresh dedicated foreign VPS IPs;
- same provider/ASN class;
- same region/host class;
- three independent Iran-side ISP connections;
- T1..T10 actually deployed;
- fourteen days of clock-synchronized observation or until frozen block criterion;
- generation-2 replacement IP only after a generation-1 block.

Until those endpoints exist, values for:

- time to first disruption;
- time to full block;
- Iran ISP-specific block type;
- volume correlation;
- IP-replacement acceleration;
- real unsolicited-probe counts;

remain **NOT MEASURED**, not zero.
