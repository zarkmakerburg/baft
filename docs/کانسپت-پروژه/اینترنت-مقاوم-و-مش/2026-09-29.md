# BAFT Concept — اینترنت مقاوم، Mesh و Island Mode

**نوع گزارش:** CONCEPT / RESILIENT MESH INTERNET  
**تاریخ:** 2026-09-29  
**وضعیت:** مفهومی / پژوهشی / آینده پروژه

## تعریف مسئله

هدف این شاخه نباید ادعای «اینترنت غیرقابل‌قطع» به معنای مطلق باشد.

اگر تمام مسیرهای فیزیکی خروجی یک منطقه واقعاً قطع شوند، هیچ پروتکل نرم‌افزاری نمی‌تواند بدون وجود یک uplink مستقل، دسترسی جهانی ایجاد کند.

تعریف دقیق‌تر:

> **BAFT Resilient Internet = شبکه‌ای که در برابر از دست رفتن Provider، Path، Gateway یا بخشی از زیرساخت تا حد ممکن زنده می‌ماند، در حالت قطع کامل به یک Internet Island محلی تبدیل می‌شود، و با بازگشت هر Gateway معتبر دوباره با جهان همگام می‌شود.**

## چهار حالت عملیاتی

### 1. Connected Mode
چند مسیر جهانی موجود است و BAFT بهترین مسیر را انتخاب می‌کند.

### 2. Degraded Mode
بعضی Providerها یا Gatewayها از دست رفته‌اند، اما شبکه هنوز حداقل یک مسیر جهانی دارد.

### 3. Island Mode
هیچ uplink جهانی در دسترس نیست. شبکه محلی باید همچنان بتواند:
- پیام محلی
- خدمات محلی
- cache محتوا
- directory محلی
- emergency information
- peer-to-peer services

را نگه دارد.

### 4. Rejoin Mode
وقتی یک Gateway معتبر دوباره ظاهر شد، داده‌های صف‌شده، metadata و stateهای لازم به‌صورت کنترل‌شده همگام شوند.

## Mesh Layer

BAFT نباید routing mesh را از صفر اختراع کند.

پروتکل‌های استانداردی مثل Babel و خانواده MANET برای شبکه‌های بی‌سیم پویا و mesh وجود دارند.

BAFT می‌تواند روی این لایه یک continuity و identity plane اضافه کند.

```
Applications
↓
BAFT Identity / Continuity
↓
Delay-Tolerant / Store-and-Forward
↓
Mesh Routing
↓
Wi-Fi / Radio / Wired / Other Links
```

## Delay-Tolerant Networking

Bundle Protocol v7 برای محیط‌هایی طراحی شده که connectivity می‌تواند:
- intermittent
- با تاخیر زیاد
- opportunistic
- unidirectional

باشد.

ایده کلیدی:

> Store → Carry → Forward

یعنی sender و receiver لازم نیست هم‌زمان online باشند.

BAFT می‌تواند برای Island Mode به جای اختراع دوباره این مفهوم، با DTN-compatible semantics کار کند.

## Local-First Internet

در قطع جهانی، هدف باید این باشد که شبکه محلی بی‌استفاده نشود.

خدماتی که می‌توانند local-first باشند:

- messaging
- local bulletin
- emergency alerts
- local maps
- local knowledge mirror
- software/document distribution
- community services
- device discovery
- local identity directory

## Content-Oriented Layer

Information-Centric Networking نشان می‌دهد محتوا می‌تواند بر اساس نام و هویت خودش بازیابی و cache شود، نه فقط محل یک server.

برای Island Mode این ایده ارزشمند است:

```
Need: /docs/emergency/latest
↓
nearest valid cached copy
```

نه الزاماً:

```
connect to one fixed server IP
```

## BAFT Island Cache

هر Node مناسب می‌تواند بخشی از محتوای عمومی و مجاز را cache کند.

ویژگی‌ها:

- content hash
- versioning
- signed metadata
- expiration
- provenance
- no implicit trust in relay

این مدل می‌تواند local availability را در زمان قطع uplink بالا ببرد.

## Gateway Federation

وقتی یک یا چند Gateway جهانی موجودند:

```
Local Mesh
├─ Gateway A
├─ Gateway B
└─ Gateway C
```

هیچ Gateway واحد نباید mandatory باشد.

BAFT باید:
- health
- trust
- capacity
- latency
- policy

را برای Gatewayها جدا نگه دارد.

## Independent Uplink

اگر همه uplinkهای معمول از بین بروند، دسترسی جهانی فقط با یک مسیر فیزیکی مستقل ممکن است.

این مسیر می‌تواند از یک technology/provider متفاوت باشد، اما BAFT نباید ماهیت خود را به یک نوع uplink خاص وابسته کند.

اصل:

> BAFT manages continuity across available links; it cannot create a physical link that does not exist.

## Opportunistic Gateway

یک Gateway ممکن است فقط گاهی ظاهر شود.

مثلاً یک Node mobile یا یک link موقت.

در این حالت BAFT می‌تواند فقط queueهای مجاز و priorityدار را همگام کند.

Priority نمونه:

1. emergency/control
2. identity/trust updates
3. messaging
4. metadata
5. bulk content

## BAFT Ferry

کانسپت پژوهشی:

یک Node که بین دو Island حرکت می‌کند می‌تواند داده‌های DTN را حمل کند.

این Node قرار نیست IP transit دائم باشد.

بلکه:

```
Island A
↓ store
Mobile Node
↓ carry
Island B
↓ forward
```

این مفهوم برای Disaster / Rural / Remote networking قابل بررسی است.

## Identity Without Central DNS

در Island Mode ممکن است DNS جهانی در دسترس نباشد.

BAFT باید بتواند حداقل identityهای محلی و service discovery را بدون dependency کامل به DNS عمومی نگه دارد.

اما naming جهانی و conflict resolution باید هنگام Rejoin با قواعد روشن انجام شود.

## Security Model

Mesh بزرگ‌تر یعنی سطح حمله بزرگ‌تر.

تهدیدها:

- malicious relay
- Sybil nodes
- fake gateway
- route poisoning
- replay
- traffic correlation
- resource exhaustion
- malicious cached content

بنابراین:

- cryptographic node identity
- signed content metadata
- trust domains
- revocation
- quota
- bounded storage
- abuse policy

ضروری‌اند.

## Privacy

Decentralized routing به‌صورت خودکار privacy نمی‌دهد.

Relayهای متعدد حتی می‌توانند metadata بیشتری ببینند.

اصل مناسب:

> minimize metadata, encrypt end-to-end, and do not equate decentralization with anonymity.

## ضدتمرکز بودن

مدل پیشنهادی:

> Federated mesh

نه:

> anonymous permissionless relay swarm

یعنی چند Trust Domain مستقل بتوانند با policy مشخص با هم federate شوند.

## Failover Hierarchy

```
Direct Internet
↓
Alternate Provider
↓
Regional Gateway
↓
Federated Gateway
↓
Island Mode
↓
DTN Rejoin
```

هدف این است که failure به‌صورت مرحله‌ای degrade شود، نه اینکه شبکه از Online مستقیماً به Dead برود.

## مفهوم «غیرقابل‌قطع»

ادعای مطلق مناسب نیست.

هیچ شبکه‌ای اگر:
- برق نداشته باشد
- radio spectrum قابل استفاده نباشد
- deviceها خاموش شوند
- تمام Gatewayهای خارجی حذف شوند

نمی‌تواند اینترنت جهانی بدهد.

ادعای فنی قابل دفاع‌تر:

> **BAFT می‌تواند شبکه را از یک زیرساخت تک‌مسیره و شکننده به یک Fabric چندمسیره، محلی‌پذیر و قابل Rejoin تبدیل کند.**

## محصول مفهومی

### BAFT Mesh
Mesh identity، routing integration، service discovery و local continuity.

### BAFT Island
Local-first services در نبود uplink جهانی.

### BAFT Bridge
Federated gateway manager برای اتصال Islandها به شبکه‌های خارجی موجود.

### BAFT Ferry
DTN/store-carry-forward برای ارتباط‌های opportunistic.

### BAFT Rejoin
همگام‌سازی امن state و queue پس از بازگشت connectivity.

## رابطه با BAFT اصلی

BAFT فعلی روی Session Continuity تمرکز دارد.

این Concept آن را گسترش می‌دهد:

```
Carrier Continuity
→ Path Continuity
→ Gateway Continuity
→ Regional Continuity
→ Island Continuity
→ Delayed Rejoin
```

## مسیر تحقیق پیشنهادی

### M1

### M2

### M3

### M4
DTN queue و delayed synchronization.

### M5
Federation بین چند Island.

### M6
Content-addressed local distribution.

### M7
Global-scale resilience experiments.

## North Star

> **A resilient Internet should degrade into a useful local network instead of collapsing into no network at all.**

BAFT اگر روزی به این سمت برود، هدفش نباید «شکست‌ناپذیری» باشد.

هدف باید:

> **Graceful survival under partial connectivity, useful operation under isolation, and safe reconnection when a path returns.**

باشد.
