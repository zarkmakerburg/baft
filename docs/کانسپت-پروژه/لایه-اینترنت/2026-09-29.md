# BAFT Concept — لایه اینترنت و پروتکل آینده

**نوع گزارش:** CONCEPT / INTERNET LAYER  
**تاریخ:** 2026-09-29

## فرضیه اصلی

BAFT نباید جایگزین IPv4/IPv6 شود. مسیر واقع‌بینانه‌تر و ارزشمندتر این است که به یک **Session Continuity & Identity Layer** روی IP تبدیل شود.

مدل پیشنهادی:

```
Application
↓
BAFT Logical Session
↓
Identity + Continuity + Path Policy
↓
TCP / QUIC / MASQUE / other carriers
↓
IP
```

## چرا جایگزینی IP مناسب نیست؟

IP یک زیرساخت جهانی با deployment عظیم است. پروتکل‌هایی مثل LISP و HIP نیز به‌جای حذف IP، تلاش کرده‌اند identity را از locator جدا کنند. QUIC هم connection migration را روی IP موجود حل می‌کند.

فضای تمایز BAFT:

- Session identity مستقل از IP
- Carrier replacement
- path failover
- state reconciliation
- node mobility در آینده
- continuity proof

## کانسپت: BAFT Continuity Protocol

یک پروتکل باز آینده می‌تواند state انتقال Session را استاندارد کند:

- SessionID
- Endpoint/Workload Identity
- Epoch
- Authority Owner
- Accepted Frontier
- Delivered Frontier
- Replay Range
- Terminal State
- Carrier Binding
- Path Metadata
- Continuity Digest

هدف این نیست که routerهای اینترنت BAFT را بفهمند؛ endpointها یا gatewayها کافی باشند.

## کانسپت: Locator/Identity/Session سه‌گانه

به‌جای دو مفهوم IP و Port:

- **Identity** = این سرویس/گره چه کسی است؟
- **Locator** = الان کجاست؟
- **Session** = کدام ارتباط منطقی باید ادامه پیدا کند؟

این می‌تواند BAFT را از overlayهای معمولی جدا کند.

## Path Awareness

BAFT می‌تواند properties مسیرهای مختلف را ببیند و انتخاب کند:

- latency
- loss
- jitter
- cost
- trust
- energy
- jurisdiction
- availability

اما نباید routing protocol جهانی جدید بسازد. Path-aware networking خود یک حوزه فعال پژوهشی است.

## کانسپت: Internet Continuity Shim

بهترین جای معماری BAFT احتمالاً بین Transport و Application است؛ نه داخل IP core.

مزیت:
- deployment تدریجی
- نیاز نداشتن به تغییر routerهای اینترنت
- امکان sidecar/gateway
- compatibility با QUIC/MASQUE

## سود/زیان

**اگر BAFT بخواهد جای IP را بگیرد:**
- Benefit: 30/100
- Risk/Cost: 95/100
- Net: -65

**اگر BAFT یک Continuity Layer روی IP باشد:**
- Benefit: 92/100
- Risk/Cost: 63/100
- Net: +29

## نتیجه

هدف پیشنهادی:

> **BAFT should not replace the Internet Protocol. BAFT should make Internet sessions less dependent on any single IP path, carrier, or node.**
