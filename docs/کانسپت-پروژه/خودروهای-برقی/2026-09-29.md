# BAFT Concept — خودروهای برقی و Connected Mobility

**نوع گزارش:** CONCEPT / ELECTRIC VEHICLES  
**تاریخ:** 2026-09-29

## فرضیه

خودروی برقی فقط یک وسیله نقلیه نیست؛ یک endpoint متحرک با چند شبکه، Cloud connection، Charging identity، telemetry و در آینده تعامل بیشتر با grid است.

BAFT می‌تواند روی **mobility continuity** کار کند، نه کنترل ایمنی خودرو.

## معماری

```
Vehicle
├─ 5G
├─ Wi-Fi
├─ Roadside network
└─ Charging network
        ↓
BAFT Mobility Layer
        ↓
OEM Cloud / Charging / Fleet / Energy services
```

## کاربردها

### Cloud Session Continuity
جابجایی خودرو بین cellular providerها یا cellها بدون از دست رفتن sessionهای non-safety-critical.

### Charging Backend Resilience
ایستگاه شارژ و backend از چند مسیر/Provider استفاده کنند تا outage یک ISP شارژ را مختل نکند.

### Fleet Connectivity
برای ناوگان تاکسی، کامیون، delivery و autonomous fleet:
- telemetry continuity
- route-data continuity
- software update control
- remote diagnostics

### V2G / Smart Charging Backend
ISO 15118 ارتباط IP-based میان EV و EVSE و سناریوهای bidirectional power transfer را پوشش می‌دهد. BAFT می‌تواند backend connectivity را مقاوم کند، ولی نباید protocol charging را جایگزین کند.

### OCPP Resilience
OCPP ارتباط استاندارد Charge Point و Central System را تعریف می‌کند. BAFT می‌تواند زیر OCPP، network failover بدهد بدون تغییر semantics آن.

### Edge Mobility
خودرو بین edge regionهای مختلف جابه‌جا شود و logical service session تا حد ممکن حفظ شود.

## حوزه‌ای که نباید وارد آن شویم

BAFT نباید برای safety-critical V2V/V2X جایگزین استانداردهای ITS/C-V2X شود.

ترمز اضطراری، collision avoidance و پیام‌های safety مستقیم باید بر استانداردهای خودرو و ITS متکی بمانند.

## کانسپت: BAFT DriveLink

- multi-network selection
- stable service identity
- cloud continuity
- charging backend resilience
- fleet observability

## کانسپت: Energy-aware Networking

خودرو می‌تواند policy داشته باشد:
- latency
- data cost
- battery impact
- signal quality

ولی AI/BAFT نباید بدون policy OEM تصمیم safety-critical بگیرد.
