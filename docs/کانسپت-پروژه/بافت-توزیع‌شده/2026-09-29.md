# BAFT Concept — معماری توزیع‌شده

**نوع گزارش:** CONCEPT / DISTRIBUTED BAFT  
**تاریخ:** 2026-09-29

## تعریف

Distributed BAFT یعنی یک سازمان یا trust authority واحد، چند Control/Relay/Edge node در Regionهای مختلف داشته باشد.

این با Decentralized BAFT فرق دارد.

```
Global BAFT Authority
├─ Region A
├─ Region B
├─ Region C
└─ Edge/Relay Nodes
```

## هدف

- حذف single-region failure
- کاهش latency
- local decision making
- horizontal scaling
- disaster recovery

## ساختار پیشنهادی

### Global Policy
قوانین و trust root.

### Regional Control
تصمیم‌های محلی، health، topology و routing.

### Edge Data Plane
Carrier و Session execution نزدیک workload.

### Witness Plane
ثبت digestهای continuity بدون payload.

## Data Ownership

Control plane جهانی نباید payload ببیند.

Regionها فقط metadata لازم برای:
- Session authority
- topology
- health
- resource accounting

را به اشتراک بگذارند.

## Failure Domains

هر Region باید بتواند در قطع Control Plane مرکزی برای مدت bounded کار کند.

اصل:

> control-plane outage ≠ immediate data-plane outage

## Consensus

برای configuration و membership می‌توان از consensus استاندارد استفاده کرد، ولی نباید هر packet یا Session frame نیازمند global consensus باشد.
