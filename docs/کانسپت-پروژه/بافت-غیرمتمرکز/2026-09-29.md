# BAFT Concept — BAFT غیرمتمرکز و Federated

**نوع گزارش:** CONCEPT / DECENTRALIZED BAFT  
**تاریخ:** 2026-09-29

## تعریف

Decentralized BAFT یعنی هیچ سازمان واحدی مالک کل Fabric نباشد.

```
Trust Domain A ─┐
Trust Domain B ─┼─ BAFT Federation
Trust Domain C ─┘
```

هر Domain:
- identity خودش
- policy خودش
- nodes خودش
- trust root خودش

را دارد و فقط رابطه federation تعریف می‌کند.

## چرا Federation بهتر از Permissionless Mesh است؟

یک mesh کاملاً permissionless برای traffic حساس مشکلات بزرگی دارد:
- Sybil
- malicious relays
- traffic correlation
- abuse
- unpredictable quality
- legal/jurisdiction risk

پس مدل پیشنهادی:

> **Federated decentralization**

نه anonymous relay swarm.

## Identity

SPIFFE نشان می‌دهد trust domainهای مستقل می‌توانند bundleهای اعتماد را برای احراز هویت cross-domain federate کنند.

BAFT می‌تواند ایده مشابهی داشته باشد:

- Domain identity
- Node identity
- Workload identity
- federation bundle
- revocation
- short-lived credentials

## Peer Connectivity

برای edge/consumer deployment می‌توان از ایده‌های P2P مانند:
- direct dialing
- NAT traversal
- hole punching
- relay fallback

یاد گرفت.

ولی relayها باید authenticated و resource-limited باشند.

## Decentralized Path Marketplace — ایده پژوهشی

Domainها بتوانند ظرفیت مسیر ارائه دهند:

- latency class
- region
- capacity
- cost
- trust score

بدون اینکه BAFT الزاماً cryptocurrency یا token داشته باشد.

ابتدا federation قراردادی/سازمانی بسیار امن‌تر است.

## Trust Score

نباید AI score تنها معیار trust باشد.

Trust باید بر:
- cryptographic identity
- operator policy
- observed reliability
- audit
- revocation

متکی باشد.

## Governance

سؤال سخت decentralization فنی نیست؛ governance است:

- چه کسی protocol version را تعیین می‌کند؟
- چه کسی abuse را مدیریت می‌کند؟
- چه کسی relay مخرب را revoke می‌کند؟
- چه کسی naming را کنترل می‌کند؟

## Privacy

مسیرهای متعدد ممکن است metadata exposure را بیشتر کنند. Decentralization به‌صورت خودکار privacy ایجاد نمی‌کند.

## نتیجه

مسیر پیشنهادی:

> **Distributed first → Federated second → Permissionless only if a real use case requires it.**

Decentralization نباید هدف ایدئولوژیک باشد؛ باید failure domain، vendor lock-in یا trust concentration واقعی را حل کند.
