# BAFT Concept — درس‌های ارتباطات تاریخی و باستانی برای شبکه آینده

**نوع گزارش:** CONCEPT / HISTORICAL COMMUNICATION SYSTEMS  
**تاریخ:** 2026-09-29  
**وضعیت:** مفهومی / پژوهشی / آینده پروژه

## ایده مرکزی

هدف این گزارش بازسازی فناوری‌های قدیمی نیست.

هدف:

> استخراج الگوهای معماری‌ای است که قبل از برق و اینترنت، شبکه‌های بزرگ برای سرعت، پایداری، تحویل مرحله‌ای، اولویت، احراز هویت و تحمل خرابی به آن رسیده بودند؛ سپس بررسی اینکه کدام الگوها می‌توانند با فناوری مدرن در BAFT دوباره تفسیر شوند.

بخش زیادی از ارزش این سیستم‌ها در «قدیمی بودن» آن‌ها نیست؛ در این است که با منابع بسیار محدود مجبور بودند مسئله شبکه را ساده و کارآمد حل کنند.

---

# 1. راه شاهی هخامنشی — Relay به‌جای End-to-End Courier

در نظام ارتباطی هخامنشی، پیام‌ها از شبکه راه‌های شاهی و ایستگاه‌های میانی عبور می‌کردند و Courier یا اسب در طول مسیر تعویض می‌شد.

اصل معماری:

> **پیام ثابت می‌ماند؛ حامل قابل‌تعویض است.**

معادل BAFT:

> **Session ثابت می‌ماند؛ Carrier قابل‌تعویض است.**

این یکی از قوی‌ترین analogهای تاریخی برای فلسفه BAFT است.

### درس برای BAFT

به‌جای اینکه یک Carrier مجبور باشد کل عمر Session را زنده بماند:

~~~
Session
  ↓
Carrier A
  ↓ failure
Carrier B
  ↓
Carrier C
~~~

Session identity و state باید از حامل جدا بماند.

---

# 2. ایستگاه‌های ازپیش‌آماده — Warm Relay

کارایی relay network تاریخی از این می‌آمد که منابع در زمان بحران تازه جست‌وجو نمی‌شدند.

اسب، Courier، استراحتگاه و مسیر از قبل آماده بودند.

معادل مدرن:

## BAFT Warm Relay Station

Nodeهای جایگزین از قبل:

- authenticated
- health-checked
- capacity-known
- policy-approved

باشند.

نه اینکه بعد از failure تازه DNS resolve، connect، authenticate، discover و negotiate از صفر شروع شوند.

---

# 3. چاپار به‌عنوان Baton Handoff

در relay تاریخی، Courier لازم نبود از ابتدا تا انتها پیام را حمل کند.

فقط مسئول segment خودش بود.

کانسپت:

## BAFT Baton

هر Carrier فقط custody یک segment از Session continuity را می‌گیرد.

Baton دیجیتال می‌تواند شامل:

- SessionID
- Epoch
- Authority
- Accepted Frontier
- Continuity Digest
- Expiry
- Previous Hop Proof

باشد.

Carrier بعدی کل history را لازم ندارد؛ فقط minimum verified state برای ادامه کار.

---

# 4. Arrival / Departure Ledger — Hop Receipt

در برخی سامانه‌های پستی تاریخی، ورود و خروج Courier از ایستگاه ثبت می‌شد.

معادل مدرن:

## BAFT Custody Receipt

هر handoff ثبت کند:

~~~
Received state X
at time T1
from node A

Transferred state Y
at time T2
to node B
~~~

نه payload؛ فقط state digest.

کاربرد:

- audit
- fault localization
- replay ambiguity
- distributed recovery
- proof of custody

---

# 5. Quipu و Compact State

شبکه Inca از chasquiهای relay استفاده می‌کرد و quipu نیز برای ثبت یا کمک به نگهداری اطلاعات به کار می‌رفت.

درس BAFT:

همه state نباید همراه Session منتقل شود.

یک state بسیار کوچک، ساختاریافته و قابل‌اعتبارسنجی می‌تواند برای continuity کافی باشد.

کانسپت:

## BAFT State Knot

~~~
Session
Epoch
Frontiers
Terminal state
Route identity
Digest
~~~

این فقط الهام مفهومی است؛ quipu یک primitive رمزنگاری نیست.

---

# 6. Beacon Networks — Control Plane فوق کم‌حجم

شبکه‌های آتش و نور تاریخی bandwidth بسیار کمی داشتند، اما برای alert و پیام‌های ازپیش‌تعریف‌شده سریع و مفید بودند.

درس:

همه control information لازم نیست verbose باشد.

BAFT می‌تواند یک:

## Ultra-Minimal Emergency Control Vocabulary

داشته باشد.

مثلاً:

- ALIVE
- DEGRADED
- ISOLATED
- REVOKED
- REJOIN
- EMERGENCY
- CAPACITY_LOW

این channel قرار نیست payload منتقل کند.

هدف:

> حفظ حداقل coordination حتی زمانی که Data Plane شدیداً degraded است.

---

# 7. Polybius / Codebook Signaling — معنای زیاد با Symbol کم

سیستم‌های signal با codebook تلاش می‌کردند مجموعه‌ای از معنی‌ها را با تعداد بسیار محدود signal منتقل کنند.

درس برای BAFT:

Control Plane نباید برای همه چیز semantic باز و payload بزرگ داشته باشد.

برای stateهای حساس، bounded vocabulary بهتر است:

- parser ساده‌تر
- ambiguity کمتر
- attack surface کمتر
- fuzzability بیشتر
- interoperability بهتر

---

# 8. Semaphore Telegraph — Hop-by-Hop Regeneration

در optical telegraph، هر ایستگاه signal ایستگاه قبلی را می‌دید و دوباره برای بعدی بازتولید می‌کرد.

الگوی مفهومی:

~~~
receive
→ decode
→ validate
→ regenerate
→ forward
~~~

کانسپت:

## BAFT Regenerative Relay

برای control traffic، Relay می‌تواند state را authenticate و validate کند و سپس frame جدید معتبر بسازد.

برای payload end-to-end encrypted، Relay نباید plaintext را ببیند.

---

# 9. Heliograph — Directional Opportunistic Link

Heliograph با نور خورشید و mirror ارتباط line-of-sight برقرار می‌کرد.

درس اصلی «نور» نیست.

درس:

> یک Link می‌تواند محدود، directional و وابسته به شرایط باشد، ولی همچنان در topology ارزشمند باشد.

BAFT باید Carrier را فقط GOOD یا DEAD نبیند.

بلکه capability-based ببیند:

- bandwidth
- latency
- availability window
- directionality
- cost
- energy
- reliability

این برای satellite، radio، vehicle mesh و opportunistic links مهم است.

---

# 10. Fire Beacon — Fast Alarm Path

سیستم Beacon برای پیام‌های کوتاه و فوری مناسب بود.

کانسپت:

## BAFT Alarm Plane

Control messageهای بحرانی لازم نیست پشت queue بزرگ data بمانند.

اما باید:

- bounded
- authenticated
- rate-limited
- non-arbitrary

باشند.

---

# 11. پیام رسمی و Seal — Capability Token

شبکه‌های پستی تاریخی معمولاً برای عموم آزاد نبودند و پیام‌رسان یا فرمان رسمی نشانه مجوز داشت.

معادل مدرن باید cryptographic capability باشد.

## BAFT Passage Token

Token کوتاه‌عمر که فقط اجازه:

- Route مشخص
- Domain مشخص
- مدت مشخص
- resource سقف‌دار

را بدهد.

نه credential عمومی و دائمی.

---

# 12. Route Diversity

امپراتوری‌های بزرگ معمولاً فقط یک مسیر نداشتند.

معادل:

~~~
Session
├─ Path A
├─ Path B
├─ Path C
└─ DTN fallback
~~~

اما مسیرها باید failure domain مستقل داشته باشند.

سه Route روی یک Provider، diversity واقعی نیست.

---

# 13. Wartime Station Density — Adaptive Infrastructure Density

در بعضی سامانه‌های تاریخی هنگام نیاز فوری، ایستگاه‌ها یا منابع relay متراکم‌تر می‌شدند.

ایده BAFT:

## Elastic Relay Density

برای workload بحرانی:

- warm relay بیشتر
- probe frequency بیشتر
- failover budget کمتر
- priority resource reserve بیشتر

برای workload عادی:

- cost optimization

---

# 14. Carrier Pigeon — Physical DTN

از دید شبکه، پرنده پیام‌رسان یک نمونه store-carry-forward فیزیکی است.

در شبکه مدرن medium متحرک می‌تواند:

- vehicle
- drone
- ship
- portable storage node

باشد.

این برای realtime مناسب نیست، اما برای disaster، disconnected region، remote sensing و bulk sync می‌تواند مفید باشد.

---

# 15. Chasqui Relay — Edge Specialization

Chasqui لازم نبود کل شبکه را بداند.

فقط segment و handoff بعدی را می‌دانست.

اصل:

> Local knowledge can be enough for global progress.

BAFT آینده نباید همه Edge Nodeها را مجبور کند topology جهانی کامل داشته باشند.

---

# 16. Separation of Message and Transport

تقریباً تمام این سامانه‌ها یک lesson مشترک دارند:

نامه، فرمان یا symbol از انسان، اسب، برج یا نور مستقل بود.

معادل:

~~~
Information ≠ Carrier
Session ≠ Carrier
Identity ≠ Locator
~~~

---

# 17. درس منفی — Human Error

شبکه‌های تاریخی failureهای مهمی داشتند:

- پیام اشتباه منتقل می‌شد
- Courier جعل می‌شد
- Signal اشتباه دیده می‌شد
- station سقوط می‌کرد
- weather ارتباط optical را می‌بست
- message تغییر می‌کرد

بنابراین نباید historical relay را romanticize کرد.

BAFT باید همان الگوها را با ابزارهای مدرن تقویت کند:

- authentication
- integrity
- sequence
- replay protection
- redundancy
- audit
- cryptographic identity

---

# 18. Relay Membership ≠ Relay Trust

در سیستم انسانی یک relay می‌توانست دروغ بگوید.

در شبکه آینده نیز باید فرض کرد بعضی relayها خراب، compromise یا buggy هستند.

Control state حساس باید cryptographically verifiable باشد.

---

# 19. New Concept — BAFT Caravan

یک Session بزرگ می‌تواند cohortهای منطقی با policy متفاوت داشته باشد:

~~~
Control Caravan
Critical Data Caravan
Bulk Caravan
Deferred Caravan
~~~

هرکدام:

- priority
- path policy
- retry policy
- retention budget

جدا داشته باشند.

این ایده فقط در صورت benchmark و مزیت measurable باید وارد طراحی واقعی شود.

---

# 20. New Concept — BAFT Relay Station

یک Relay Station آینده می‌تواند چهار نقش داشته باشد:

### Stable
Carrier فعال.

### Fresh Horse
Warm standby آماده.

### Inn
Buffer یا DTN محدود.

### Watchtower
Health، telemetry و alert.

این abstraction می‌تواند mental model خوبی برای Edge BAFT باشد.

---

# 21. New Concept — Proof-of-Passage

هر انتقال حساس میان Nodeها یک proof کوچک بسازد:

~~~
Node A
↓
signed custody digest
↓
Node B
~~~

Proof نشان دهد:

- کدام Session
- کدام Epoch
- کدام frontier
- چه زمان
- از چه Domain
- به چه Domain

منتقل شده است.

این می‌تواند future Continuity Certificate را به یک audit chain محدود تبدیل کند.

Blockchain لازم نیست.

# 22. Graceful Information Degradation

Beaconها نشان می‌دهند وقتی bandwidth بسیار کم است، هنوز می‌توان مهم‌ترین اطلاعات را منتقل کرد.

BAFT آینده می‌تواند در congestion شدید:

~~~
Full service
↓
critical control + interactive
↓
control only
↓
emergency beacon
~~~

degrade شود.

نه اینکه:

~~~
100% → 0%
~~~

# 27. مهم‌ترین کشف مفهومی

قدیمی‌ترین شبکه‌های مؤثر یک اصل بسیار مدرن داشتند:

> **سرعت لزوماً از سریع‌ترکردن یک حامل به دست نمی‌آید؛ گاهی از حذف زمان خستگی، آماده‌سازی و failure با handoffهای کوتاه و منابع آماده به دست می‌آید.**

برای BAFT:

> شاید کمترین recovery time نه با Carrier قوی‌تر، بلکه با Carrierهای مستقل‌تر و ازپیش‌آماده به دست بیاید.

# North Star

> **Ancient networks survived distance by handing the message forward. BAFT can survive failure by handing the session forward.**
