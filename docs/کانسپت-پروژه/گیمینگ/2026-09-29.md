# BAFT Concept Gaming — Global Low-Latency Fabric

**نوع گزارش:** CONCEPT / GAMING  
**تاریخ:** 2026-09-29  
**وضعیت:** مفهومی / آینده پروژه

## ایده اصلی

BAFT Gaming نباید «VPN مخصوص بازی» باشد.

تعریف بهتر:

> **BAFT Gaming = Adaptive Low-Latency Path Fabric**

سیستم باید Direct path و مسیرهای BAFT را مقایسه کند و فقط وقتی وارد مسیر شود که اندازه‌گیری واقعی نشان دهد بهتر است.

## معیار اصلی

هدف نباید فقط کمترین average ping باشد.

بهینه‌سازی باید روی:

- RTT
- jitter
- packet loss
- p95 latency
- p99 latency
- packet reordering
- path stability

باشد.

یک مسیر 45ms پایدار می‌تواند از مسیر 30ms با spikeهای 120ms تجربه بهتری بدهد.

## Gaming Plane جدا

Carrier فعلی H2/TCP برای realtime gaming ایده‌آل نیست.

در آینده بهتر است دو Plane جدا وجود داشته باشد:

```
BAFT
├── Reliable Continuity Plane
│   └── TCP / ECRL / critical streams
└── Realtime Gaming Plane
    └── UDP / QUIC DATAGRAM / low queue
```

Gaming Plane باید بر transportهای استاندارد و UDP-native تکیه کند.

## کانسپت‌ها

### Stable Game Egress

Game Server یک public egress ثابت ببیند، حتی اگر مسیر داخلی BAFT عوض شود.

### Warm Gaming Paths

A = Active  
B = Warm  
C = Warm

در degradation مسیر A، B از قبل health-checked باشد.

### Predictive Path Switching

با مشاهده روند:

- RTT
- jitter
- loss

قبل از failure شدید مسیر تغییر کند؛ با hysteresis برای جلوگیری از path flapping.

### Hedge Datagram

برای packetهای بسیار latency-critical، نسخه دوم bounded روی path جایگزین فرستاده شود و egress duplicate را حذف کند.

این feature باید محدود و آزمایشی باشد چون bandwidth و complexity اضافه می‌کند.

### Adaptive Micro-FEC

برای loss کوچک ولی مداوم، parity محدود و adaptive بررسی شود.

### Jitter Shield

micro-reorder محدود و با budget چند میلی‌ثانیه؛ نه jitter buffer بزرگ.

### Game Atlas

Telemetry بدون payload و با privacy:

- ISP ASN
- coarse region
- game region
- time bucket
- RTT
- jitter
- loss
- route quality

برای ساخت نقشه کیفیت جهانی Gaming Internet.

### Group Latency Optimizer

برای team session هدف فقط کمترین ping یک نفر نباشد؛ می‌توان max latency یا variance بین بازیکنان را کمینه کرد.

### Cloud Gaming

دو traffic class:

- Input: tiny + ultra-low latency
- Video: high bandwidth + controlled queue

هرکدام policy مسیر جدا.
