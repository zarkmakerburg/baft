# BAFT — چشم‌انداز جهانی

**نوع گزارش:** GLOBAL VISION & STRATEGY  
**تاریخ:** 2026-09-29  
**وضعیت:** مفهومی / پژوهشی / خارج از scope اجرایی Step 5.7

## ایده مرکزی

BAFT نباید صرفاً به‌عنوان یک VPN یا Tunnel دیده شود.

تعریف بلندمدت پیشنهادی:

> **BAFT = Stateful Connection Continuity Fabric**

یعنی یک لایه که تلاش می‌کند هویت و state یک Session منطقی را از Carrier و Path فیزیکی جدا کند.

اصل پایه:

- Carrier ≠ Session
- Path ≠ Session
- Process ≠ Session
- Node ≠ Session

## جایگاه بالقوه در اینترنت

BAFT می‌تواند روی مسئله‌ای متمرکز شود که بسیاری از فناوری‌های موجود فقط بخشی از آن را حل می‌کنند:

> حفظ continuity یک Session منطقی هنگام تغییر یا شکست Carrier فیزیکی.

فناوری‌هایی مثل QUIC، MPTCP، Multipath QUIC، MASQUE، Tailscale، ZeroTier، Cloudflare Tunnel و SPIFFE هرکدام بخش‌هایی از mobility، multipath، identity یا relay را حل می‌کنند. BAFT نباید آن‌ها را دوباره اختراع کند؛ مزیت بالقوه باید در **state reconciliation و continuity correctness** باشد.

## معماری بلندمدت پیشنهادی

```
Application
    ↓
Logical Session Identity
    ↓
Continuity Plane / ECRL
    ↓
Carrier Abstraction
    ↓
H2 | QUIC | MASQUE | future standard carriers
    ↓
Path Plane
    ↓
Internet / Private Networks
```

### لایه‌ها

1. **Identity Plane**  
   هویت Node/Workload مستقل از IP، چرخش گواهی، trust domain و attestation.

2. **Control Plane**  
   BCC، topology، health، policy، finance و orchestration.

3. **Continuity Plane**  
   ECRL، authority، replay، tombstone، session migration و continuity proof.

4. **Carrier Plane**  
   H2 فعلی، و در آینده transportهای استاندارد دیگر.

5. **Path Plane**  
   Direct، secondary، relay، regional relay و multi-access.

6. **Observability Plane**  
   metrics، logs، traces، audit و recovery timeline.

## کانسپت‌های آینده

### Continuity Certificate

برای هر handoff یک artifact کوچک شامل:

- SessionID
- Epoch
- Candidate
- Flow-state digest
- Acceptance frontier digest
- Terminal-state digest
- timestamp/sequence
- امضای دو peer

بدون ذخیره payload.

### Warm Carrier Pool

چند Carrier از قبل authenticated و health-checked باشند:

- Active
- Warm standby
- Probe-only

تا failure نیازمند connect/authenticate از صفر نباشد.

### Path Broker

BCC بتواند topology را بر اساس:

- RTT
- Loss
- Capacity
- Cost
- Health
- Region
- Historical stability

تحلیل کند و policy محدود و explainable اجرا کند.

### Multi-Carrier Session

یک Logical Session بتواند چند Carrier داشته باشد، اما authority مشخص کند چه Carrierی اجازه mutation دارد.

### Session Mobility

در آینده دور، Session از یک process یا Node به Node دیگر منتقل شود بدون اینکه معنای منطقی Session از بین برود.

### Application Continuity API

Application بتواند eventهایی مثل:

- recovery_started
- recovery_complete
- path_changed
- degraded
- healthy

را دریافت کند.

## اصل رمزنگاری

BAFT نباید cryptography اختصاصی اختراع کند.

راهبرد:

> Adopt standards; do not invent cryptography.

معماری باید crypto-agile باشد تا بتواند در آینده از استانداردهای TLS و post-quantum hybrid استفاده کند.

