# 26 — P1-D: فهرست سرورها و راه‌اندازی با SSH

یک سرور به BCC اضافه می‌شود و `baft-agent` از راه SSH روی آن نصب می‌شود؛ دیگر لازم نیست دستی وارد سرور تازه شوی. جزئیات در [نسخهٔ انگلیسی](../en/26-p1d-ssh-bootstrap.md).

## فعال‌سازی

<div dir="ltr" align="left">

```
baft-bcc ... --install-script /opt/baft/install.sh --public-url https://bcc.example.com
```

</div>

بدون این دو گزینه، endpointها جواب `501` می‌دهند.

## مراحل

1. **خواندن host key** (چیز محرمانه‌ای فرستاده نمی‌شود): `POST /api/bootstrap/hostkey` با `host` و `port`. اثر انگشت برگشتی را با چیزی که پنل سرویس‌دهنده نشان می‌دهد مقایسه کن.
2. **نصب** با اثر انگشتِ تأییدشده: `POST /api/bootstrap` با `node_id`، `host`، `user`، `host_key_fingerprint` و یکی از `password` یا `private_key`.

BCC نود را می‌سازد، توکن تازهٔ agent تولید می‌کند، با host key پین‌شده وصل می‌شود و `install.sh --agent-only` را روی سرور اجرا می‌کند. agent نسخهٔ امضاشده را دانلود و با کلید Root پین‌شده تأیید و سرویس `baft-agent` را روشن می‌کند. تونل‌ها بعداً از BCC اضافه می‌شوند.

## قواعد امنیتی

- **بدون اعتماد در اولین اتصال:** بدون اثر انگشت `SHA256:` نصب انجام نمی‌شود و اگر سرور کلید دیگری نشان بدهد، پیش از ورود قطع می‌شود.
- **رمز و کلید SSH فقط در حافظه:** در state، لاگ audit، بکاپ و لاگ‌ها نمی‌رود و از خطاها و خروجی حذف می‌شود.
- **هیچ رازی در خط فرمان نیست:** توکن agent و کلید job روی stdin می‌روند.
- **رمز بدون رمزنگاری نمی‌رود:** فقط با TLS یا از loopback قبول می‌شود.
- **audit:** میزبان، پورت، کاربر، روش ورود و اثر انگشت ثبت می‌شود، نه رمز.
- هم‌زمان فقط یک نصب؛ تلاش دوباره، توکن تازه می‌سازد و قبلی را باطل می‌کند.

## هنوز نیست

فرم در داشبورد (فعلاً API) و تست کامل روی یک سرور SSH واقعی در CI (P1-F).
