# 32 — منوی `baft` و هدر ترمینال

HQ A3 (منو و هدر). اجرای `baft` روی ترمینال (یا `baft menu`) یک منوی شماره‌دار روی خود سرور باز می‌کند، با خط‌های ساده و بدون raw mode، پس روی SSH و گوشی هم کار می‌کند. جلوی چیزهایی است که از قبل هست. **فقط‌خواندنی است، جز support bundle که بعد از یک «بله»ی صریح یک آرشیو می‌نویسد، و Uninstall (۱۳) که همان روند `baft uninstall` را اجرا می‌کند (سند ۳۴): اول plan دقیق، بعد تأییدهای جداگانه (هر دستهٔ داده پیش‌فرض NO، تونل‌های فعال، و تایپ `uninstall`)**. هر چیزی که هنوز ساخته نشده با `(planned)` علامت می‌خورد و هنگام انتخاب همین را می‌گوید. هرگز نصب، تعمیر، به‌روزرسانی، restart، adopt یا ویرایشی انجام نمی‌دهد.

فرمان‌های مستقیم (`baft status`، `baft doctor --json`، `baft logs`، `baft version`، ...) **بدون تغییرند: بدون splash و بدون escape sequence**، مناسب اسکریپت. بدون ترمینال، `baft` مثل قبل usage چاپ می‌کند و با کد ۲ خارج می‌شود و `baft menu` رد می‌کند.

## منو

| # | گزینه | چه می‌کند |
|---|---|---|
| 1 | Overview / Status | `baft status` |
| 2 | Doctor | اجرای `baft doctor` یا پیش‌نمایش fixها (دستورها نشان داده می‌شود، هرگز اجرا نمی‌شود) |
| 3 | Servers | شناسه، نقش و وضعیت agent همین سرور؛ سرورها در BCC مدیریت می‌شوند |
| 4 | Tunnels (this node) | موجودی محلی فقط‌خواندنی: unitهای BAFT، واقعیت‌های config و ownership marker (همان خواندن discovery، سند ۳۱)؛ طبقه‌بندی MANAGED/DRIFTED/... با BCC است |
| 5 | BCC | وضعیت سرویس BCC روی این میزبان و فرمان‌های BCC که باید روی میزبان BCC اجرا شود |
| 6 | Monitoring | متریک‌های محلی نود؛ مانیتورینگ ناوگان و سلامت در BCC است |
| 7 | Certificates | فایل‌های CA و گواهی که config نام برده: subject، انقضا، روزهای باقی‌مانده (`WARNING` زیر ۳۰ روز، `FAILED` وقتی منقضی است) |
| 8 | Backup / Restore | راهنمای backup، فرمان فقط‌خواندنی `baft-bcc restore-preview` و restore محلی/offline با `baft-bcc restore ... --yes` |
| 9 | Logs | ۱۰۰ یا ۵۰۰ خط آخر (برای دنبال‌کردن زنده `baft logs -f`) |
| 10 | Support bundle | بعد از «بله»ی صریح آرشیو عیب‌یابی secret-safe را می‌نویسد |
| 11 | Update | **planned** |
| 12 | Repair | **planned** |
| 13 | Uninstall | زیرمنوی HQ: ۱ فقط باینری‌ها، ۲ فقط agent، ۳ فقط BCC، ۴ سرویس‌ها + باینری‌ها، ۵ حذف کامل، ۶ پیش‌نمایش، ۰ بازگشت؛ هر گزینه اول plan را نشان می‌دهد و بدون تأییدها چیزی حذف نمی‌کند (سند ۳۴) |
| 14 | Advanced | بررسی config، اطلاعات release، agent، عیب‌یابی شبکه، اطلاعات debug، اطلاعات سرویس، ownership/drift، مسیرهای محلی، نسخه و build |
| 0 | Exit | همچنین `q`، `exit` یا پایان ورودی |

پرچم‌ها: `--file`، `--service`، `--release-state`، `--unit-dir`، `--state-dir`، `--agent-unit`، `--bcc-service`. هر رشته‌ای که از میزبان می‌آید (hostname، config، فایل unit) و هر چیزی که کاربر تایپ می‌کند قبل از چاپ از کاراکتر کنترلی پاک می‌شود، پس هیچ escape sequenceی به ترمینال نمی‌رسد. نمای Tunnels از آداپتر systemd استفاده می‌کند که هر چیزی جز `systemctl is-active` را رد می‌کند.

**Health** در هدر یک حکم سریع محلی است (وضعیت سرویس و متریک loopback: `HEALTHY`، `DEGRADED`، `DOWN` یا `UNKNOWN`) بدون probe راه دور، تا منو فوری باز شود؛ تصویر کامل `baft doctor` است.

## هدر ترمینال

هدر یک برداشت ANSI/Unicode/ASCII از لوگوی رسمی است، نه کپی پیکسلی: یک **B طلایی بافته**، کابل فنی مشکی در حلقه‌هایش، خط‌های عمودی طلایی شبکه و گره‌های طلایی، بعد `B A F T` و *Resilient Network Fabric*، بعد Version، Node، Role، Health و Release. تصویر، فونت، شبکه یا وابستگی ندارد و انیمیشن هم ندارد (چیزی چشمک نمی‌زند، نمی‌چرخد و فرمانی را به تأخیر نمی‌اندازد).

پالت: طلایی اصلی `#D4AF37`، طلایی روشن `#FFD76A`، طلایی تیره `#9B6A12`، خنثی‌های سفید/خاکستری/زغالی؛ رنگ وضعیت فقط برای وضعیت (سبز سالم، طلایی هشدار، قرمز down، خاکستری نامعلوم). خود برند طلایی می‌ماند.

**تشخیص قابلیت ترمینال** قبل از رسم هر چیز:

| حالت | چه وقت |
|---|---|
| `FULL_COLOR` | ترمینال با `COLORTERM=truecolor` یا `24bit` |
| `256_COLOR` | ترمینالی که `TERM` آن `256color` دارد |
| `MONOCHROME` | ترمینال بدون رنگ، یا `NO_COLOR` تنظیم‌شده (کاملاً رعایت می‌شود: هیچ escape رنگی نیست) |
| `PLAIN` | stdout ترمینال نیست یا `TERM=dumb`: بدون گرافیک، دو خط ساده |

Unicode به locale با UTF-8 نیاز دارد (`LC_ALL`/`LC_CTYPE`/`LANG`)؛ وگرنه کل هدر به ASCII برمی‌گردد (`+-|`، `#=.`، `o`). عرض از ترمینال (یا `COLUMNS`، وگرنه ۸۰) می‌آید: **WIDE** (۱۰۰ ستون یا بیشتر، mark بزرگ کنار عنوان و اطلاعات)، **NORMAL** (۷۰ تا ۹۹، mark کوچک بالای آن‌ها) و **COMPACT** (زیر ۷۰، دو خط برای گوشی: `BAFT ◈ v0.1.2` و `node · role · HEALTH`). رنگ هرگز تنها نشانگر نیست: سلامت همیشه به شکل کلمه چاپ می‌شود.
